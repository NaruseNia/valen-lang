## REQ-SYNTAX-001: キーワード・識別子・リテラルの字句定義

| 項目 | 内容 |
|------|------|
| **ID** | REQ-SYNTAX-001 |
| **優先度** | Must |
| **ステータス** | Done |
| **依存** | — |
| **説明** | Valen 言語のソースファイル（`.vln`、UTF-8）を構成するキーワード・予約語・識別子・リテラル・演算子の字句定義を確定し、logos ベース lexer で実装する。 |

### 受け入れ基準

- [x] キーワード一覧が確定している: `fn let mut self return if else match class data enum trait impl pub internal private open abstract sealed override package import for in while loop break continue true false as`
- [x] 予約語（将来用）が定義されている: `suspend async await yield typealias`
- [x] 識別子ルール `[a-zA-Z_][a-zA-Z0-9_]*` が lexer に実装されている
- [x] 数値リテラル（整数、`L` サフィックス付き Long、浮動小数点、`f` サフィックス付き Float）が字句解析可能
- [x] 文字列リテラル（`"..."` ダブルクォート）が字句解析可能
- [x] 真偽値リテラル（`true` / `false`）がキーワードとして認識される
- [x] 演算子（`==` `!=` `===` `!==` `::` `.` `+` `-` `*` `/` `=` `<` `>` `<=` `>=` `&&` `||` `!` `?` `@`）が字句解析可能
- [x] `@` が annotation 予約 sigil として登録され、MVP では Valen コード内で `@` を識別子前に置くとパーサエラーとなる
- [x] `static` キーワードは導入しない（仕様確定）
- [x] lexer の snapshot テストが `insta` で 5 ケース以上存在する

## REQ-SYNTAX-002: セミコロンルール（Rust 流3分類）

| 項目 | 内容 |
|------|------|
| **ID** | REQ-SYNTAX-002 |
| **優先度** | Must |
| **ステータス** | Draft |
| **依存** | REQ-SYNTAX-001 |
| **説明** | Valen の `;` は Rust 流の3分類に従う。文末必須・ブロック式省略可・余分な `;` 許容の3ルールをパーサで正しく処理する。 |

### 受け入れ基準

- [ ] **文末 `;` 必須** — `let` / `return` / 単純な式文（`foo();` 等）の末尾に `;` がない場合パーサエラーとなる
- [ ] **ブロック式は statement position で `;` 省略可** — `if` / `match` / `for` / `while` / `loop` / `{}` の直後に `;` がなくてもパーサエラーにならない
- [ ] **余分な `;` は empty statement として許容** — `if cond { ... };` が合法（valenfmt で除去推奨）
- [ ] ブロック式を値として右辺に置く場合、`let` 文末の `;` が必須であることを検証: `let x = if y > 0 { y } else { -y };`
- [ ] ブロック末尾に `;` を置いた場合、ブロックの値が unit 化されることを型チェックで検証
- [ ] statement position の定義（関数本体・ブロック中のトップレベル要素位置）が実装に反映されている
- [ ] セミコロン3分類のパーサテストが各カテゴリ最低2ケースずつ存在する

## REQ-SYNTAX-003: コメント（単行・ブロック・doc）

| 項目 | 内容 |
|------|------|
| **ID** | REQ-SYNTAX-003 |
| **優先度** | Must |
| **ステータス** | Done |
| **依存** | REQ-SYNTAX-001 |
| **説明** | 単行コメント `//`、ブロックコメント `/* ... */`、ドキュメントコメント `///` の3種を lexer で正しくスキップまたはトークン化する。 |

### 受け入れ基準

- [x] `//` 以降の行末までが単行コメントとしてスキップされる
- [x] `/* ... */` が複数行にわたるブロックコメントとしてスキップされる
- [x] `///` がドキュメントコメントとして認識される（将来の doc 生成用途に保持可能）
- [x] コメント内の文字列がトークンとして誤認識されない
- [x] コメントの lexer テストが `insta` で存在する
