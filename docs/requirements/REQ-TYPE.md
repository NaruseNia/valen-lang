## REQ-TYPE-001: プリミティブ名義型

| 項目 | 内容 |
|------|------|
| **ID** | REQ-TYPE-001 |
| **優先度** | Must |
| **ステータス** | Draft |
| **依存** | REQ-SYNTAX-001 |
| **説明** | Valen の全プリミティブ型を名義型として定義する。JVM 上の対応する型へのマッピングは実装詳細として仕様では保証しない（例: `Int` は「JVM 整数型に対応する名義型」まで）。 |

### 受け入れ基準

- [ ] 以下の型が Valen のプリミティブ名義型として定義されている: `Int`, `Long`, `Float`, `Double`, `Char`, `Bool`, `Byte`, `Short`, `String`, `Unit`, `Nothing`
- [ ] 各型がパーサで型注釈として認識される（`let x: Int = 42;`）
- [ ] `Unit` が戻り値なし関数のデフォルト戻り値型として機能する
- [ ] `Nothing` が底型として型チェッカーで正しく扱われる（例: `panic` の戻り値型）
- [ ] JVM 上の boxing/unboxing は仕様に露出しない（実装内部の最適化に留める）
- [ ] 各プリミティブ型のバイトコード emit が正しく JVM 型にマッピングされる

## REQ-TYPE-002: リテラルデフォルト型

| 項目 | 内容 |
|------|------|
| **ID** | REQ-TYPE-002 |
| **優先度** | Must |
| **ステータス** | Draft |
| **依存** | REQ-TYPE-001 |
| **説明** | 数値・文字列・真偽値リテラルのデフォルト型とサフィックスルールを確定する。 |

### 受け入れ基準

- [ ] 整数リテラル `42` のデフォルト型が `Int` である
- [ ] `L` サフィックス付き整数 `42L` の型が `Long` である
- [ ] 浮動小数点リテラル `3.14` のデフォルト型が `Double` である
- [ ] `f` サフィックス付き浮動小数点 `3.14f` の型が `Float` である
- [ ] 文字列リテラル `"hello"` の型が `String` である
- [ ] 真偽値リテラル `true` / `false` の型が `Bool` である
- [ ] サフィックスなし整数を `Long` 型変数に代入すると型ミスマッチエラーとなる（`let y: Long = 42;` → ERROR）
- [ ] 不正なサフィックス（例: `42D`）がパーサまたは型チェッカーでエラーとなる

## REQ-TYPE-003: 暗黙数値変換なし・明示変換メソッド

| 項目 | 内容 |
|------|------|
| **ID** | REQ-TYPE-003 |
| **優先度** | Must |
| **ステータス** | Draft |
| **依存** | REQ-TYPE-001 |
| **説明** | 暗黙の数値変換（widening 含む）を一切行わない。全ての数値型変換は明示変換メソッドによる。オーバーロード解決が型完全一致のみ候補となることを保証する。 |

### 受け入れ基準

- [ ] `let x: Long = 42;` が型ミスマッチのコンパイルエラーとなる
- [ ] `let x: Long = 42.toLong();` が正しくコンパイルされる
- [ ] `let z: Double = 3.14f.toDouble();` が正しくコンパイルされる
- [ ] 変換メソッド一覧が全て実装されている: `.toInt()`, `.toLong()`, `.toFloat()`, `.toDouble()`, `.toByte()`, `.toShort()`, `.toChar()`
- [ ] `Int + Long` のような異なる数値型間の演算がコンパイルエラーとなる
- [ ] 暗黙 widening が発生しないことを検証するテストが存在する
- [ ] エラーメッセージが「暗黙変換は行われない、明示変換メソッドを使え」旨を案内する

## REQ-TYPE-004: 等値比較（== 構造 / === 参照）

| 項目 | 内容 |
|------|------|
| **ID** | REQ-TYPE-004 |
| **優先度** | Must |
| **ステータス** | Draft |
| **依存** | REQ-TYPE-001 |
| **説明** | `==` を構造比較（`.equals()` 脱糖）、`===` を参照比較（JVM 参照一致）として定義し、4演算子を実装する。 |

### 受け入れ基準

- [ ] `==` が `.equals()` 呼び出しに脱糖される
- [ ] `!=` が `!.equals()` 呼び出しに脱糖される
- [ ] `===` が JVM 参照一致比較に emit される
- [ ] `!==` が JVM 参照不一致比較に emit される
- [ ] `data class` の `==` が自動生成 `equals` による構造比較で動作する
- [ ] `===` で同一オブジェクト参照を判定できることを検証するテストが存在する
- [ ] 4演算子全てのバイトコード emit が正しいことを検証するテストが存在する

## REQ-TYPE-005: Option\<T\> による null 一本化（T? 糖衣）

| 項目 | 内容 |
|------|------|
| **ID** | REQ-TYPE-005 |
| **優先度** | Must |
| **ステータス** | Draft |
| **依存** | REQ-TYPE-001 |
| **説明** | Valen の欠損表現を `Option<T>` に一本化する。`T?` を `Option<T>` の糖衣構文として提供し、`null` リテラルを Valen コード上で使用不可とする。 |

### 受け入れ基準

- [ ] `Option<T>` が `valen.core` で定義され、`Some(T)` / `None` variant を持つ
- [ ] `T?` がパーサで `Option<T>` の糖衣として認識・展開される
- [ ] `null` リテラルが Valen ソースコード中でコンパイルエラーとなる
- [ ] `T!`（platform type）はユーザ記述不可であり、IDE 警告表示のみに使用される
- [ ] Java 相互運用時に Java の `null` 戻り値が `Option<T>` の `None` に変換される（`safe {}` ブロック内）
- [ ] `Option<T>` に対する `?` 演算子で `None` 伝播ができる
- [ ] `match` で `Option` variant を分解できる: `Some(x) => ...`, `None => ...`

## REQ-TYPE-006: ジェネリクス（erasure, in/out variance）

| 項目 | 内容 |
|------|------|
| **ID** | REQ-TYPE-006 |
| **優先度** | Must |
| **ステータス** | Draft |
| **依存** | REQ-TYPE-001, REQ-CLASS-001 |
| **説明** | `<T>` 形式のジェネリクスを提供する。JVM 互換のため erasure ベースとし、宣言時 variance（`in` / `out`）を指定可能とする。`reified` は Phase 2 送り。 |

### 受け入れ基準

- [ ] class / trait / fn にジェネリクスパラメータ `<T>` を宣言できる
- [ ] `out T`（共変）をジェネリクス宣言で指定可能（例: `trait Iterator<out T>`）
- [ ] `in T`（反変）をジェネリクス宣言で指定可能
- [ ] erasure が JVM バイトコードに正しく反映される（実行時に型パラメータが消去される）
- [ ] ジェネリクス型の制約（`<T: Trait>`）が型チェッカーで機能する
- [ ] `reified` は MVP で未実装であり、使用時にコンパイルエラーとなる
- [ ] ジェネリクスを使った class / trait / fn のバイトコード emit テストが存在する

## REQ-TYPE-007: typealias（所有権なし）

| 項目 | 内容 |
|------|------|
| **ID** | REQ-TYPE-007 |
| **優先度** | Should |
| **ステータス** | Draft |
| **依存** | REQ-TYPE-001, REQ-TRAIT-003 |
| **説明** | `typealias` で型の別名を定義できる。ただし所有権を生まないため、orphan rule 判定上 typealias は元の型の所有として扱われない。 |

### 受け入れ基準

- [ ] `typealias UserId = Int;` がパーサ・型チェッカーで正しく処理される
- [ ] typealias 先の型と元の型が型チェッカーで同一型として扱われる
- [ ] typealias を介した orphan rule 回避が禁止される（`typealias MyList = java.util.List<Int>` に対する trait impl がコンパイルエラー）
- [ ] typealias のジェネリクスパラメータ転送が正しく動作する（`typealias StringMap<V> = Map<String, V>`）
- [ ] typealias が JVM バイトコードに直接現れない（コンパイル時解決のみ）

## REQ-TYPE-008: ローカル型推論あり・fn シグネチャ明示

| 項目 | 内容 |
|------|------|
| **ID** | REQ-TYPE-008 |
| **優先度** | Must |
| **ステータス** | Draft |
| **依存** | REQ-TYPE-001 |
| **説明** | ローカル変数では型推論を許可する（`let x = 42;` で `Int` 推論）。一方、関数シグネチャ（引数型・戻り値型）は明示必須とする。 |

### 受け入れ基準

- [ ] `let x = 42;` が型注釈なしでコンパイル可能（`Int` に推論）
- [ ] `let s = "hello";` が `String` に推論される
- [ ] `fn foo(x: Int) -> Int { ... }` の引数型・戻り値型が省略不可であり、省略時コンパイルエラーとなる
- [ ] 関数の引数型を省略した場合のエラーメッセージが「fn シグネチャは明示必須」旨を案内する
- [ ] 戻り値型を省略した場合のエラーメッセージが同様に案内する（`Unit` 戻り値も省略不可か、省略時 `Unit` とするかは仕様確認要）
- [ ] 複雑な式（例: `let x = if cond { 1 } else { 2 };`）でも正しく型推論が動作する
- [ ] ジェネリクスのローカル推論が動作する（`let list: List<Int> = ...;` のような場面）
